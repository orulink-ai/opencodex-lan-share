# opencodex LAN Share - Security

## Threat Model

opencodex LAN Share is designed for **trusted office LAN environments**. It assumes:
- All machines on the LAN are trusted
- The network is behind a NAT/firewall (no public internet exposure)
- Physical access to the server machine is restricted

## What's Protected

### Provider API Keys (YOUR keys)

Your Alibaba Cloud, DeepSeek, and OpenAI API keys are stored **only** in `~/.opencodex/config.json` on the server machine. They are never transmitted to client machines. The proxy uses these keys internally to call upstream providers.

### Access Keys (colleague keys)

Each colleague gets a separate **access key** generated by `ocx access key create`. These are admission tokens — they allow the colleague to send requests through your proxy, but do not expose your provider keys.

## Best Practices

### 1. Use Access Keys (Not Direct Sharing)

**DO:** Generate individual access keys per colleague.
```
ocx access key create "Zhang San"
ocx access key create "Li Si"
```

**DON'T:** Share your admin token or provider API keys with anyone.

### 2. Firewall: Private Profile Only

The `setup-lan.ps1` script creates a firewall rule restricted to Windows Firewall **Private** profile. This means:
- Port 10100 is open when on your office network (Private profile)
- Port 10100 is **automatically closed** when connecting to public WiFi (Public profile)

Verify your network is set to Private:
```powershell
Get-NetConnectionProfile | Select-Object Name, NetworkCategory
```

### 3. Rotate Keys Regularly

```powershell
# Revoke old, create new
.\scripts\server\manage-users.ps1 -Rotate <key-id>

# Also rotate provider keys periodically on their respective dashboards
```

### 4. Monitor Usage

```powershell
# Check who's using what
ocx observe usage

# Check quota status
ocx quota
```

### 5. No Public Internet Exposure

**NEVER** set up port forwarding on your router for port 10100. The proxy uses **plain HTTP** (no TLS), so traffic over the public internet would be unencrypted. If remote access is needed, use Tailscale or a VPN.

### 6. Revoke Immediately on Departure

When a colleague leaves:
```powershell
.\scripts\server\manage-users.ps1 -Revoke <key-id>
```

## What's NOT Protected

- **Traffic within LAN is unencrypted** (HTTP, not HTTPS). Anyone on the same LAN segment could potentially sniff traffic. This is acceptable for office LANs but a consideration for sensitive code.
- **No rate limiting per user** (by default). All colleagues share the same provider rate limits.
- **No content filtering**. The proxy passes all requests through to providers.

## Server Machine Security

The server machine should:
1. Have a strong Windows login password
2. Auto-lock after inactivity
3. Have Windows updates enabled
4. Not be used for browsing untrusted websites
5. Have the `~/.opencodex/` directory permissions restricted to the admin user

## Incident Response

If you suspect a security issue:

1. **Revoke all access keys immediately:**
   ```powershell
   ocx access key list | ForEach-Object { ocx access key remove $_.id --yes }
   ```

2. **Rotate provider API keys** on their respective dashboards (Alibaba Cloud, DeepSeek, OpenAI)

3. **Update opencodex config** with new keys:
   ```powershell
   ocx provider update <provider> --api-key <new-key>
   ocx restart
   ```

4. **Generate new access keys** for legitimate colleagues

5. **Review usage logs:**
   ```powershell
   ocx observe usage --since 7d
   ```
